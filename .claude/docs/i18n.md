# Internazionalizzazione (Transloco)

## Setup

| Pezzo | File |
| --- | --- |
| Provider | `src/app/app.config.ts` (`provideTransloco`) |
| Loader HTTP (browser) | `src/app/i18n/transloco-loader.ts` |
| Loader prerender (server) | `src/app/app.config.server.ts` |
| Config CLI/keys-manager | `transloco.config.ts` (root) |
| Traduzioni | `public/assets/i18n/it.json`, `public/assets/i18n/en.json` |

Config: `defaultLang: 'it'`, `availableLangs: ['it', 'en']`, `failedRetries: 2`,
`reRenderOnLangChange: true`.

Il loader richiede `./assets/i18n/<lang>.json?cb=<timestamp>` — il cache-buster
evita che il service worker serva traduzioni vecchie dopo un deploy.

Un `APP_INITIALIZER` (`appInitializerFactory`) attende il caricamento della
lingua di default **prima** del primo render, quindi non si vedono mai chiavi
grezze all'avvio.

## Il loader è doppio

Nel **browser** `TranslocoHttpLoader` scarica il JSON via HTTP.

Durante il **prerender** non esiste un server da cui scaricarlo e una URL
relativa non risolve in Node: il bootstrap fallirebbe e la build si fermerebbe
con `NG0401`. Per questo `app.config.server.ts` sostituisce il loader con uno
che restituisce i JSON importati a build time:

```ts
import it from '../../public/assets/i18n/it.json';
{ provide: TRANSLOCO_LOADER, useClass: ServerTranslocoLoader }
```

Quel file finisce solo nel bundle server, quindi le traduzioni **non** vengono
duplicate nel bundle browser. Richiede `resolveJsonModule: true` in
`tsconfig.json`.

Conseguenza pratica: se cambi il modo in cui le traduzioni vengono caricate,
devi aggiornare **entrambi** i loader, altrimenti la build passa e il sito
prerenderizzato esce con le chiavi grezze (o non esce affatto).

## Usare le traduzioni

Nel template (via pipe, si aggiorna al cambio lingua):

```html
<h2>{{ 'projects.hero.all.titleHtml' | transloco }}</h2>
<p>{{ 'contact.description' | transloco }}</p>
```

Nella classe (valore una tantum, **non** reattivo):

```ts
private readonly _t = inject(TranslocoService);
label = this._t.translate('menu.home');
```

Se usi `translate()` devi ri-tradurre al cambio lingua, come fa `HeaderComponent`:

```ts
this._translateService.langChanges$.subscribe(() => {
  this.menuItems.set(this._layoutService.getMenuItems());
});
```

Per questo motivo: **preferisci sempre la pipe**.

## Struttura delle chiavi

Namespace di primo livello presenti:

```
exceptions  menu     intro     experience  projects  work
tecnologies contact  update    common      toggle    drawer
alert       warning  genericWarning        errors    primeng
```

Convenzioni:

- Namespace = area/feature, poi camelCase: `projects.hero.dev.titleHtml`.
- Suffisso `Html` quando il valore contiene markup renderizzato con `innerHTML`
  (`<strong>`, `<br>`).
- Chiavi dinamiche costruite a runtime: `projects.hero.${mode}.titleHtml`,
  `toggle.badge.${mode}`. **Se aggiungi una portfolio mode devi aggiungere tutte
  le varianti di queste chiavi**, altrimenti la UI mostra la stringa grezza.
- I valori possono essere array (es. `intro.roles`) per i testi a rotazione.
- `primeng.*` contiene le stringhe dei componenti PrimeNG (il caricamento nel
  config PrimeNG è commentato nel loader, quindi oggi non sono applicate).

## Regola: le due lingue restano allineate

Ogni chiave aggiunta va in `it.json` **e** in `en.json`. Verifica:

```bash
node -e "
const fs=require('fs');
const flat=(o,p='')=>Object.entries(o).flatMap(([k,v])=>v&&typeof v==='object'&&!Array.isArray(v)?flat(v,p+k+'.'):[p+k]);
const it=flat(JSON.parse(fs.readFileSync('public/assets/i18n/it.json','utf8')));
const en=flat(JSON.parse(fs.readFileSync('public/assets/i18n/en.json','utf8')));
console.log('mancanti in en:', it.filter(k=>!en.includes(k)));
console.log('mancanti in it:', en.filter(k=>!it.includes(k)));
"
```

Oppure il comando `/i18n-check`.

## Disallineamento attuale (settembre 2026)

283 chiavi in `it.json`, 209 in `en.json`.

- **78 mancanti in `en.json`** — quasi tutte sotto `primeng.*` (calendario,
  paginator, filtri), più `intro.rolePrefix`.
- **4 mancanti in `it.json`** — `projects.figma`, `cookie.consentMessage`,
  `cookie.accept`, `cookie.reject`.

Non è un bug bloccante (il blocco `primeng` non è collegato), ma quando tocchi
uno di quei namespace allinea entrambi i file.

## Cosa NON tradurre

- Le `label` dei tag progetto in `projects.data.ts`: sono identificatori di
  filtro, non testo UI.
- I nomi dei progetti e i campi `nome`/`descrizione` del modello (contenuto
  scritto direttamente in italiano nei dati).
- I nomi delle tecnologie.
